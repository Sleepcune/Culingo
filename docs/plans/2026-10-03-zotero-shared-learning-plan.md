# CuLingo for Zotero 10.0.5：PDF 阅读与共用学习数据库执行规划

规划日期：2026-10-03。

**目标：**在 Zotero 原版 PDF 阅读器中提供生词高亮、查词、收藏、整篇按需双语阅读和闪卡复习；与现有 Chrome／Edge 版共用生词本、掌握状态、例句和复习进度。

**架构：**优先使用小型 Windows 本机服务统一保存学习数据，浏览器扩展与 Zotero 插件作为两个入口。首先验证服务资源占用及 PDF 定位能力；服务超过约定资源上限时，按已经确定的取舍改由 Zotero 插件承担数据服务。

**技术栈：**现有浏览器端继续使用 WXT、TypeScript、React；Zotero 端使用 TypeScript、React 与 Zotero 插件生命周期，打包为 XPI；独立服务使用 Go、标准 HTTP 服务和 SQLite；两个客户端复用同一版本的 ts-fsrs。

## 一、已确认的产品决定

| 项目 | 决定 |
| --- | --- |
| 首要平台 | 本机 Windows 64 位、Zotero 10.0.5 |
| 首要阅读场景 | Zotero 原版 PDF 页面，保留论文布局 |
| 英语学习 | 英语识别、简体中文释义，复用现有 ECDICT 词库 |
| 两端关系 | 共用一套学习记录，不要求日常手动导入导出 |
| 翻译范围 | 单词、短语、句段、当前页，以及随阅读位置更新的整篇双语侧栏 |
| 数据位置 | 本机，首版无账号、无云同步 |
| 独立服务标准 | 程序及运行所需二进制合计 ≤30 MiB；空闲工作集 P95 ≤60 MiB |
| 超过资源标准 | 改为 Zotero 承担数据服务；共用学习时需要保持 Zotero 运行 |
| 安装交付 | Zotero XPI、更新后的浏览器扩展 ZIP、本机服务及安装／备份说明 |

资源标准不包含离线词库、学习数据库、缓存和备份；交付时分别列出这些实际占用。上述数字是验收上限，当前没有运行新增服务，不能当作已经测得的性能。

**首版不包含：**扫描 PDF 的 OCR、生成完整译文 PDF、把中文重排进原 PDF、自动写入 Zotero 原生批注、EPUB／网页快照、Zotero 重排阅读模式、手机端、多电脑同步、跨用户共享和视频字幕。

本次已读取本机安装文件，确认版本为 10.0.5、BuildID 为 20260930221031。Zotero 官方说明其插件运行在应用内部，Zotero 10 基于 Firefox 140 ESR，因此需要专门的 Zotero 插件宿主适配。[插件开发说明](https://www.zotero.org/support/dev/client_coding/plugin_development)、[Zotero 10 开发说明](https://www.zotero.org/support/dev/zotero_10_for_developers)

## 二、用户最终如何使用

### 1. PDF 中的阅读流程

打开英文 PDF → 自动标出生词 → 悬停约 250 毫秒查词 → 收藏单词和所在句子 → 在另一篇论文或浏览器网页中再次遇到 → 继续提示 → 在任一入口复习。

查词卡显示原文词形、标准词形、本地释义、可用音标和词性。已有用户编辑释义优先展示，并与词典原释义、模型译文分开。收藏保存论文标题、附件标识、页码、原句和定位信息。

绿色提示超过当前词频档位的词，金色提示学习中的词，已掌握的词不自动提示。3000／5000／8000 档位沿用浏览器版，默认 5000；用户对具体词形的明确状态优先于词典还原结果。

### 2. 整篇双语阅读

- 原 PDF 保留在原阅读区域，CuLingo 侧栏依次显示对应的英文段落与中文译文。
- 手动开启“整篇双语”后，先处理当前可见段落及下一页少量内容；随着翻页继续，避免一次发送整篇论文。
- 提供“翻译所选文字”“翻译当前页”“跟随阅读位置”“暂停”“关闭双语”等操作。
- 点击侧栏段落可定位原文；手动浏览侧栏时暂停自动跟随，点击“跟随”后恢复。
- 关闭后取消待执行请求和订阅，保留已经生成的本地缓存；不会删除论文、原批注或学习记录。
- 此版本的“整篇”表示可以贯穿整篇阅读，不包括后台批量预翻译全部页面或导出译文 PDF。

### 3. 两端共用数据

在 Zotero 收藏的词会出现在浏览器生词本中；在浏览器标记掌握后，Zotero 中同词的学习提示更新；任一端完成复习后，另一端取得相同的到期时间。

学习记录只有一个权威数据库。客户端保留只读缓存以加快打开速度，不能在失联后静默切换成第二套可写生词本。

| 运行情况 | 可用行为 |
| --- | --- |
| 无外网、本机服务正常 | 本地查词、高亮、收藏、生词本、复习、备份正常；在线翻译不可用 |
| Zotero 关闭、本机服务正常 | 浏览器继续完整学习；论文跳转通过 Zotero 协议启动应用 |
| 本机服务退出或无法连接 | 使用最后缓存查词／高亮和查看记录；暂停收藏、编辑、评分及共享在线翻译，提供启动／重连入口 |
| Zotero 托管方案中 Zotero 关闭 | 等同于数据服务离线，不创建另一个可写数据库 |

未启用“共用学习空间”的原浏览器独立模式保留。成功迁入共用空间后，该空间不再同时写入旧 IndexedDB；回到独立模式必须显式导出／迁回，防止数据分叉。

## 三、架构、复用与关键实现决定

### 1. 模块划分

保持现有浏览器工程入口，新增三个明确边界：

| 模块 | 责任 |
| --- | --- |
| `packages/shared` | 平台无关的词汇规则、规范化、类型／协议、FSRS 计算、导入导出规则；独立导出可复用的 React 界面 |
| `apps/zotero` | 插件启动和卸载、PDF ReaderAdapter、查词卡与双语侧栏、来源定位、Zotero 设置入口 |
| `apps/service` | Go 服务、SQLite、配对鉴权、唯一学习数据库、原子写入、变更通知、翻译代理、备份与本机启动管理 |

浏览器与 Zotero 界面通过统一 ClientTransport 调用数据服务。现有 `browser.runtime`、`browser.storage` 和 Dexie 读写保留在浏览器适配层，不让共享模块直接依赖它们。

复用现有 ECDICT 固定版本、词形映射和测试样本；词库为可重建的只读资源，可在客户端保留副本。学习数据、词库、翻译缓存分别管理，清理缓存不能触及学习数据。

Go 服务使用 `modernc.org/sqlite` 的固定版本及匹配依赖，不要求用户安装 Go、Node 或 Python 运行时。该驱动支持 Windows amd64，且不依赖 CGo。[驱动文档](https://pkg.go.dev/modernc.org/sqlite)

### 2. 本机服务与启动方式

- 服务只监听 `127.0.0.1`，默认端口 43119；端口冲突时显示明确提示并允许统一修改，不扫描随机端口自动认领服务。
- 以当前 Windows 用户身份运行，不申请管理员权限，不安装系统级常驻服务。提供启动、停止、状态和“登录后启动”开关；自启动由安装界面显式勾选，默认关闭。
- 使用单实例锁；重复启动只连接已有实例，不同时打开两套写入者。进程意外退出后由入口提示重启，进程恢复不清空数据库。
- 数据默认位于 `%LOCALAPPDATA%\CuLingo\data\learning.sqlite`。日志和缓存独立限额，日志不记录正文、API 密钥和配对令牌。
- SQLite 使用事务、外键和 WAL；备份使用在线备份或事务快照，不直接复制一个正在写入的主数据库文件。
- 服务端 API 密钥及服务端配对凭据使用 Windows 当前用户 DPAPI 保护。浏览器配对令牌只存于限制可信扩展上下文访问的存储区，Zotero 配对令牌只向插件特权上下文开放；不把客户端存储描述为 DPAPI 加密。导出学习备份不包含任何凭据。

### 3. 首阶段的资源决策门槛

原型必须包括真实 SQLite 驱动、协议和配对处理、变化订阅、秘密存储及翻译代理，而不是只测一个空 HTTP 服务。

测试数据固定为 1 万词汇、2 万例句、5 万复习日志；词库及缓存正常接入。连接两个客户端后停止操作，预热结束后每秒采样，连续 5 分钟记录：程序大小、工作集、私有内存、CPU 和唤醒次数。

程序二进制总计 ≤30 MiB、空闲工作集 P95 ≤60 MiB，且 CPU 平均低于单核 1% 时保留独立服务。只允许一轮明确的资源优化后复测；仍超标则切换 Zotero 托管，不在两个完整服务实现上同时投入。

备用方案保持相同领域模型、备份格式、事务规则和客户端接口，由 Zotero 的独立插件数据库与自定义本机端点实现。浏览器改用 Zotero 本机服务地址；按 Zotero 10 的要求携带请求头，仍需 CuLingo 自己的配对鉴权。运行时不在两种宿主之间自动切换。[Zotero 10 本机接口约束](https://www.zotero.org/support/dev/zotero_10_for_developers#local_http_server_and_local_api)

### 4. 配对和本机通信

- 首次连接使用由本机启动器打开的配对窗口，生成两分钟有效的一次性随机配对凭据；每个客户端获得单独的 256 位随机令牌，可以撤销。
- 生产请求必须鉴权，并校验 Host。浏览器请求只接受已配对的扩展 Origin；拒绝普通网站 Origin、`null` Origin 和通配 CORS。Zotero 特权请求可以没有 Origin，但仍必须携带令牌。
- 浏览器网页脚本只能调用允许的后台消息，不能读取本机令牌、API 密钥，也不能传入任意本机 URL。
- 协议带 `protocolVersion`、`datasetId`、`epoch` 和单调递增 `revision`。每次重新连接先握手；恢复备份、更换数据库或宿主后，旧缓存不能继续按旧 revision 写入。
- 使用可重连的变化订阅通知已连接客户端。可见阅读页面每 2 秒检查一次轻量 revision 作为兜底，由浏览器后台合并多标签请求；隐藏页面停止轮询。浏览器后台被挂起时不保证连接常驻，重新唤醒、标签页重新激活及任何写入前补取增量或完整快照。
- 在线且活跃的两个入口，状态更新目标为 2 秒内可见；休眠入口在重新激活并完成握手后更新。

### 5. 共用复习进度与并发规则

为保留现有调度行为，两端直接复用锁定的 `ts-fsrs 5.4.2` 及同一套参数，不另写 Go 版记忆算法。保持目标记忆保持率 0.9、关闭随机扰动，每天全空间最多引入 20 个新词，到期卡优先。

复习分为“准备”和“提交”：用户点击评分时才发起准备请求，服务返回当前卡片、revision、服务端 UTC 时间及 60 秒有效的评分凭据；客户端共享核心算出下一状态；服务在一个事务中验证凭据、算法版本、数据结构、卡片 revision、掌握状态和当天额度，并提交卡片与日志。结果中的评分时间必须与准备请求一致，凭据过期则重新准备，不能复用过期计算。日界线按学习空间配置的 IANA 时区计算，默认取当前系统时区。

客户端是已配对的可信应用，服务不重复实现 FSRS 数学。服务是最终进度的唯一提交者：

- 同一 `operationId` 和同一内容重试返回原结果；同编号不同内容拒绝。
- 两端同时给同一卡评分，第一笔有效提交成功，第二笔收到“卡片已更新”，刷新后继续，不累计两次。
- 删除或标记掌握后，未提交的评分拒绝；重新学习保留原调度，不重建新卡。
- 释义与状态修改附预期 revision；冲突时展示最新记录，不靠电脑时钟盲目覆盖。
- 新词 20 个是整套学习空间的额度，不是每端各 20 个。跨午夜的过期评分凭据要求刷新。

### 6. Zotero 插件与 PDF 适配

插件使用 Zotero 的启动、窗口加载、关闭和卸载生命周期。通过 `Zotero.Reader.registerEventListener` 接入选择弹窗与工具栏，通过条目面板扩展提供 CuLingo 侧栏；这些 API 已在本机 10.0.5 程序代码中核对存在。[阅读器扩展接口](https://www.zotero.org/support/dev/zotero_7_for_developers#custom_reader_event_handlers)

自动高亮需要的页面字符、矩形和渲染事件不全部属于稳定公共 API，统一封装进 `ReaderAdapter10`，在启动时做能力检测，不把内部属性访问散落到业务代码中。首版实测目标锁定 10.0.5；其他 10.0 补丁版需回归后列入支持清单。

- 读取已渲染页面的文本／字符位置，构建“规范化词汇 → 原文字符 → PDF 坐标”映射。
- 在页面上加入属于 CuLingo 的轻量 SVG 覆盖层，绘制半透明提示和下划线，`pointer-events:none`；不把每个生词保存成 Zotero 原生批注，也不修改 PDF 文件。
- 用同一坐标映射完成悬停命中、缩放、页面旋转、单双页和高 DPI 变换，原始选择与批注继续由 Zotero 处理。
- 默认处理可见页面及前后各一页，页级缓存最多保留 8 页；页面销毁、附件关闭和插件卸载时释放索引、覆盖层及事件监听。
- 拖选、正在绘制批注或打开原生选择弹窗时暂停悬浮卡片，避免抢焦点。
- 多栏和段落顺序优先取已验证的 Zotero 结构化文本；缺失时按页内分栏及行坐标还原。低置信度区域不自动跨栏拼接，改为用户选区翻译。
- 跨行连字符只在词典可以确认合并结果时还原；保留多个原文矩形。页眉页脚、纯公式和非正文区域不默认作为连续英文段落。
- 没有文本层的扫描页提示暂不支持；附件未下载时提供 Zotero 原有下载／打开入口，不把“没有本地文件”误报成词典故障。

能力检测失败时保留能工作的选择查词，并给出清楚的兼容性提示；这属于运行时降级，不视为“自动高亮”验收通过。

### 7. 翻译与发音

两端共享翻译服务配置与缓存。Go 主服务承担请求、并发与缓存；Zotero 托管路线使用现有 TypeScript 翻译模块的宿主适配。兼容 Chat Completions，根地址、密钥、模型字段沿用现有约定。

- 远程服务必须 HTTPS；回环地址允许 HTTP。配置和测试只在可信设置界面进行，页面只能提交待翻译文本。
- 全局最多 2 个外部请求，每段最多约 2000 字符，长段按句子拆分；25 秒超时，401／403 停止当前任务队列，429／5xx 最多重试一次。
- 文本、服务、模型、语言及提示词版本共同决定缓存；相同任务合并。取消一端请求不取消另一端仍需的共享请求。
- 选择翻译优先于当前页，当前页优先于全文预取。关闭标签或切换附件取消所属等待任务，迟到响应不能插入另一篇论文。
- 译文作为纯文本渲染；只发送要翻译的段落，不上传 PDF 文件、文献目录或学习数据库。
- 缓存采用 LRU，总容量上限 50 MiB，已产生的外部 API 费用不能撤回。
- 单词发音在客户端使用可用的系统英语语音；不要求云语音。Zotero 和浏览器分别做语音能力检测，缺失时显示原因，其他学习功能继续可用。

## 四、数据、内部接口与现有数据迁移

### 1. 数据对象的变化

| 对象 | 新增或调整 |
| --- | --- |
| 学习词汇 | 保留现有 ID 与学习状态，增加服务端 revision；新增收藏统一规范化，已有导入词形不静默改 ID |
| 例句 | 来源改为网页或 Zotero 附件两种类型，允许同词同时有网页和论文例句 |
| Zotero 来源 | 实例标识、个人库／群组库标识、父条目与附件 key、标题、页序号、显示页码、原文矩形、引文上下文、文件指纹 |
| 复习卡和日志 | 保留现有 FSRS 状态、到期时间和历史，增加算法版本与提交编号 |
| 学习空间 | 数据集 ID、epoch、revision、每日新词上限、时区和公共词频档位 |
| 客户端状态 | 配对身份、最近同步游标、只读缓存；站点开关、窗口布局、主题等保留各端偏好 |
| 删除记录 | 增量同步携带删除标记，避免另一端缓存让已删词重新出现 |

PDF 定位保存零基页序号和显示页码两种值，不把论文印刷页码当作文件页数。附件身份使用库与 key，避免依赖容易变化的文件路径或数据库数字 ID。文件指纹由阅读器文件标识和本地文件版本信息组成，用于识别定位可能失效，不作为安全散列保证。

点击“回到原文”时，Zotero 根据附件身份打开并定位；附件变化时优先在原页匹配引文，无法可靠匹配则只打开该页并提示。备份恢复到另一 Zotero 实例后，需要关联当前资料库，不按碰巧相同的 key 静默关联错误文献。

### 2. 最小接口集合

| 接口组 | 约定 |
| --- | --- |
| `bridge.handshake / pair / revoke` | 版本、数据集身份、配对与撤销 |
| `dictionary.lookup / classify` | 复用词典与词频规则，可合并用户编辑释义 |
| `vocabulary.save / setStatusById / edit / remove / list` | 服务端事务和 revision 校验，收藏幂等 |
| `review.getQueue / prepare / commit` | 获取队列、确定评分时间／版本、原子提交 FSRS 结果 |
| `changes.subscribe / since / snapshot` | 通知与补取变化；游标过期取得完整快照 |
| `translation.translate / cancel` | 请求归属到客户端及文档，允许共享任务但独立取消 |
| `source.open` | 只接受已保存的结构化来源，生成受控网页／Zotero 跳转，不提供任意文件执行入口 |
| `settings.getPublic / update / configureApi` | 阅读设置与密钥分离，普通调用不返回密钥 |
| `backup.export / preview / import` | v2 完整备份、v1 兼容迁入、预览及事务合并 |

普通变更请求按小批次处理；备份通过受限大小的专用导入接口。标准错误码区分未配对、服务离线、卡片过期、修订冲突、来源失效和存储不足，UI 不再依靠中文错误文本判断恢复动作。

### 3. 从浏览器 v0.1 迁移

1. 共用空间配置完成后，浏览器展示已有词汇、例句、卡片和日志数量，先导出 v1 原始备份。
2. 暂停该浏览器学习数据写入，取得一致快照；不传出词典、翻译缓存和 API 密钥。
3. 预览转换为 v2 的结果；首次迁移为空中心库时保留全部现有 ID、FSRS 字段与历史，新增 Zotero 来源结构不破坏旧网页来源。
4. 使用带 migrationId 和摘要的事务导入；重复执行返回同一结果，不重复建词或日志。
5. 校验各对象数量、规范化导出摘要、例句关联及复习到期时间；成功后切换数据源。失败时继续原独立模式，不能停在一半迁移状态。
6. 旧 IndexedDB 保留为回滚副本，不自动删除。API 配置由单独的可信设置操作转移，成功后浏览器使用中心配置。

已有中心数据的合并沿用现有规则：词汇编辑按更新时间选择较新内容，卡片采用最近复习状态，日志按 ID 去重。同时间但不同内容列为冲突，默认保留中心记录并生成导入报告；例句按来源和原文去重。日常同步不使用这套时间戳合并，日常修改采用 revision 校验。

v2 备份包含共享学习记录、Zotero 来源和学习空间设置，不包含密钥、配对凭据或外部服务会话。CSV／Anki TSV 保留词汇、释义、例句和可点击来源；浏览器 v0.1 不承诺读取 v2，须先更新到本次交付的浏览器版。

## 五、分阶段执行顺序

按单人开发配合 AI 辅助估算，约 **24—34 个有效开发日，另安排一周日常试用**。这是工作量区间，PDF 布局和插件兼容性是主要浮动因素。

| 阶段 | 估算 | 实施工作 | 必须交付与验收 |
| --- | --- | --- | --- |
| 0：两项高风险验证 | 3—4 天 | 独立 Zotero 开发配置；最小 XPI 加载／卸载；实际 PDF 字符定位与覆盖层；真实依赖的服务资源样机 | 双栏 PDF 的选择、复制、缩放和原批注正常；停用覆盖层完全消失；资源报告明确选择独立服务或 Zotero 托管 |
| 1：共享核心与协议 | 2—3 天 | 抽出平台无关词汇／FSRS／导入规则及界面传输接口；增加 v2 来源和协议类型 | 现有浏览器构建与测试通过；相同评分输入的状态、到期时间和计数一致，浮点字段按固定容差验证 |
| 2：唯一学习数据库 | 4—5 天 | 实现选定宿主的 SQLite、配对、revision、事务、变化订阅、复习提交及安全退出 | 两个模拟客户端同时收藏不重复；同一卡不能被重复评分；服务重启后记录与 revision 完整 |
| 3：浏览器接入和迁移 | 2—3 天 | 增加共用空间设置、来源渲染、迁移预览／回滚、失联提示和补取变化 | 现有浏览器记录迁入后数量与进度一致；旧独立模式仍可用；新共用模式不双写 |
| 4：PDF 阅读版本 | 4—6 天 | 页面级文本映射、频率高亮、悬浮卡、选择入口、收藏例句、跨端掌握刷新和原文回跳 | 从论文收藏后浏览器能看到；浏览器标记掌握后论文提示更新；多栏、旋转、缩放、窗口重开通过 |
| 5：整篇双语侧栏 | 4—6 天 | 句段和当前页翻译、阅读顺序、按需全文模式、侧栏跟随、优先级、缓存、取消和鉴权故障恢复 | 完成一篇双栏论文的连续阅读；恢复原文无残留；关闭旧论文后不会出现迟到译文；重复段落命中缓存 |
| 6：共用生词本、复习和备份 | 2—3 天 | 复用管理界面、来源筛选、全空间统计、评分恢复、v2 备份与旧备份兼容 | 任一端复习后的到期时间一致；全空间每天最多 20 新词；干净环境恢复网页及论文例句和调度 |
| 7：兼容、性能和交付 | 3—4 天 | Chrome／Edge 与 Zotero 真机验收、服务资源复测、冲突插件回归、升级／卸载测试和打包 | 交付 XPI、ZIP、选定宿主服务组件、中文说明、测试报告和回滚步骤 |

**执行检查点：**先完成阶段 0 的资源与 PDF 可行性证明，再迁移真实学习数据；阶段 4 形成第一个可日常使用的 Zotero 阅读版本，之后完成整篇双语和交付验证。

每个阶段先加入有意义的失败用例，再实现、执行相关验证和审查。客户端纯逻辑用 Vitest；独立服务用 Go 测试和临时 SQLite；浏览器继续 Playwright。Zotero 在独立配置和数据目录中运行集成探针并结合真机操作，不能用浏览器测试替代 Zotero 宿主验证。

### 2. 性能目标

- 记录本机硬件和软件版本；所有目标在词库可用后测量。
- PDF 当前页文本与渲染就绪后，约 1000 英文词的可见区域在 500 ms 内出现高亮；不把 Zotero 自己打开 PDF 的耗时算入。
- 离线查词往返 P95 <200 ms，包含本机 IPC，不包含 250 ms 悬停等待。
- 已连接、活跃的两端在 2 秒内反映收藏、掌握和评分结果。
- 增量扫描按 ≤8 ms 小批次运行，避免 CuLingo 连续占用主线程超过 50 ms。
- 在 200 页论文上逐页阅读，页级缓存保持有界；重复打开／关闭测试不出现持续增长的监听器和覆盖层。
- 服务首次与最终交付各做一次资源验收，采用同一测试集和计量方法；分别报告空闲、翻译中和大量导入的峰值，不把空闲预算表述为所有负载的硬上限。

### 3. 最终验收链路

安装与配对 → 将浏览器 v0.1 数据迁入 → Zotero 打开英文 PDF → 高亮并查词 → 收藏词汇及论文例句 → 浏览器看到该词 → 浏览器标记掌握 → PDF 提示更新 → 开启并关闭整篇双语 → 任一端评分 → 另一端显示相同进度 → 重启服务与两端 → 导出备份 → 在干净环境恢复 → 从例句回到 PDF 原页。

这条链路必须在真实 Zotero 10.0.5 和至少一个日常使用的 Chrome／Edge 配置中通过。随后连续一周实际阅读，记录阻断阅读、定位错乱、状态不同步和数据恢复问题；自动测试通过不能替代这项试用验收。

## 七、交付、依赖与后续边界

交付包含：Zotero XPI、浏览器扩展 ZIP、独立服务压缩包和用户级启动管理工具（若采用备用路线，则交付 Zotero 托管组件）、完整源代码、版本锁文件、词库许可证、API 配置说明、共用数据迁移说明、备份／恢复／卸载说明、资源实测表与验证报告。

卸载任一客户端不会自动删除中心学习数据库。卸载数据服务默认保留数据和备份，清空学习记录必须走独立明确操作。升级先备份，再运行事务迁移；失败时保留原库和错误信息，不新建空库假装恢复。

JavaScript 依赖安装在项目本地 `node_modules`，Go 工具链和模块／构建缓存也放在项目工具目录，不改全局环境。如果后续确需 Python 数据处理，使用 uv 和项目本地 `.venv`。

后续版本可独立考虑 Zotero 重排阅读模式、EPUB、OCR、多电脑共享和原生注释／笔记导出；它们不作为本次交付的隐含依赖。

**执行优先级：先证明 PDF 原版阅读稳定，再证明两端确实读写同一套学习记录，最后完善整篇双语体验。**
